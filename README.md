**Требования**

- Unity 6000.3.25f1 (Unity 6.3 LTS). Другие версии Unity могут сохранять сцены в несовместимом формате.
- Git 2.23 или новее.

**Установка и запуск**

1. Склонировать репозиторий: `git clone https://github.com/re1ampag0/lab2-unity.git`
2. В Unity Hub: Projects → Add → Add project from disk → папка репозитория. При первом открытии Unity создаёт папку Library, это занимает несколько минут.
3. Открыть сцену `Assets/IndieMarc/PlatformerDemo/PlatformerDemo.unity` и нажать Play.

Управление: A и D - движение, Space - прыжок (доступен двойной прыжок), S - приседание.

Готовая сборка под Windows доступна в разделе Artifacts последнего успешного запуска на вкладке Actions.

**Структура репозитория**

- `Assets/` - ассеты проекта, игровая сцена находится в `Assets/IndieMarc/PlatformerDemo/`
- `Packages/` - список пакетов Unity
- `ProjectSettings/` - настройки проекта
- `docs/` - документация проекта
- `.github/workflows/` - конфигурация GitHub Actions

Папки Library, Temp, Logs, UserSettings и неиспользуемый вариант шаблона TopDownDemo исключены из репозитория через `.gitignore`.

**Порядок внесения изменений**

1. Изменения проекта выполняются в отдельных ветках с именем вида `тип/описание`: `feature/` - изменения уровня, `fix/` - исправление ошибок, `docs/` - документация, `ci/` - настройка сборки. Небольшие правки документации допускается вносить сразу в main.
2. Коммиты оформляются по правилам из [docs/conventions.md](docs/conventions.md): заголовок `тип(область): что сделано` на русском языке, один коммит - одно изменение.
3. После отправки ветки на GitHub автоматически запускаются тесты и сборка (см. раздел «Автоматическая проверка и сборка»). Ветка сливается в main командой `git merge --no-ff` только после успешного запуска.
4. Слитые ветки удаляются локально и на GitHub.

Найденные ошибки регистрируются в Issues. Коммит с исправлением содержит в описании `Fixes #номер`, и Issue закрывается автоматически после попадания коммита в main.

**Автоматическая проверка и сборка**

Конфигурация находится в [.github/workflows/main.yaml](.github/workflows/main.yaml). Workflow запускается при каждом push в любую ветку, а также вручную на вкладке Actions.

1. Тесты Unity Test Framework в режимах playmode и editmode выполняются параллельно.
2. При успешном прохождении тестов выполняется сборка под Windows (StandaloneWindows64).
3. Отчёты тестов и собранная игра сохраняются в разделе Artifacts на странице запуска во вкладке Actions, откуда их можно скачать.

Данные лицензии и учётной записи Unity хранятся в защищённых переменных репозитория (Settings → Secrets and variables → Actions): `UNITY_LICENSE`, `UNITY_EMAIL` и `UNITY_PASSWORD`. Их значения не видны в коде и логах и не попадают в репозиторий.
